`.agents` это ваша рабочая папка для AI. Здесь лежат правила, skills, промты,
специалисты и всё остальное, что вы собрали за время работы. Codex, Claude,
Gemini, Kimi и другие инструменты могут пользоваться одной папкой по очереди
или одновременно.

Это не новая нейросеть и не новый аккаунт. `.agents` хранит ваши материалы
отдельно от конкретного сервиса. Поменяете компьютер, аккаунт или AI-инструмент,
а работа останется в вашем Git-репозитории.

## Зачем это нужно

| Что случилось | Как поможет `.agents` |
| --- | --- |
| У Claude закончился лимит или доступ | Подключите Codex, Gemini или Kimi и продолжайте с теми же правилами и skills |
| Купили новый компьютер | Клонируйте свою `.agents` и запустите установку. Привычная среда вернётся |
| Один AI делает работу, другой должен её проверить | Дайте им разные роли; задания, ответы и проверки останутся в одном месте |
| Собрали удачные промты и рабочие приёмы | Они принадлежат вам, а не одному аккаунту или сервису |
| Появился новый формат или инструмент | Создайте для него папку. Старые материалы не придётся переделывать |

## Быстрый старт: три шага

### 1. Установите

Нужны Git и Python 3. На macOS, Linux или WSL скопируйте и выполните:

```bash
git clone https://github.com/bearatol/.agents.git
cd .agents
./scripts/agents.sh setup
```

На Windows:

```powershell
git clone https://github.com/bearatol/.agents.git
Set-Location .agents
.\scripts\agents.ps1 setup
```

Установщик спросит:

- для какой работы вам нужны помощники: код, тексты, видео, исследования или всё сразу;
- какими AI-приложениями вы пользуетесь.

Можно выбрать несколько вариантов, а AI-приложения ввести через запятую. `generic`
выбирайте только для инструмента без собственного адаптера. Перед установкой вы
увидите, что изменится.

### 2. Проверьте установку

```bash
./scripts/agents.sh doctor
```

На Windows:

```powershell
.\scripts\agents.ps1 doctor
```

`doctor` проверит установленную среду и подключения. Если он сообщает о
конфликте или изменённом файле, сначала разберитесь с этим сообщением.

### 3. Перезапустите выбранный AI-инструмент и дайте задачу

После перезапуска приложение увидит общие материалы, которые умеет читать.

Например:

> Проверь этот проект на ошибки. Сначала составь короткий план, затем внеси изменения и покажи результаты тестов.

После проверки терминал в ежедневной работе больше не нужен.

## Хотите сразу всё и несколько AI

Хотите подключить всё сразу и работать с несколькими AI? Выполните одну команду:

```bash
./scripts/agents.sh setup --work all \
  --app codex --app claude --app gemini --app kimi
```

На Windows:

```powershell
.\scripts\agents.ps1 setup -Work all -App codex,claude,gemini,kimi
```

Позже можно добавить ещё один AI. Остальное переустанавливать не придётся:

```bash
./scripts/agents.sh connect kimi
```

## Что сохраняется

В вашем Git-репозитории `.agents` можно хранить:

- ваши правила и промты;
- skills и специалисты;
- настройки моделей и описания подключений;
- общие задачи, ответы и проверки нескольких AI;
- новые типы материалов в отдельных папках.

Пароли, API-ключи, авторизация, установленные программы и веса моделей сюда не
попадают. Их нельзя хранить в Git.

## Как добавить свою наработку

Пример для собственного skill:

```bash
./scripts/agents.sh library add skill my-skill ./my-skill
./scripts/agents.sh library trust skill my-skill
./scripts/agents.sh library activate skill my-skill
./scripts/agents.sh connect codex claude gemini kimi
```

Сначала добавьте материал, потом подтвердите, что вы его проверили. Это защита:
инструкции из файлов не должны включаться сами по себе. После активации
подключённые AI смогут использовать skill.

Можно хранить и другие типы: `rule`, `prompt`, `agent`, `mcp`, `model` и свои
папки. Когда для нового типа появится адаптер, его можно будет подключить без
переноса старых файлов.

## Переезд на новый компьютер

Если личных материалов нет, снова клонируйте `.agents` и запустите `setup`.

Если добавляете свои правила и skills, храните их в собственном приватном
Git-репозитории. На новом компьютере:

```bash
git clone YOUR_PRIVATE_REPOSITORY .agents
cd .agents
./scripts/agents.sh setup
./scripts/agents.sh library check
./scripts/agents.sh doctor
```

Git вернёт ваши файлы, а `setup` подключит приложения. Личные skills нужно снова
включить командой `library activate skill НАЗВАНИЕ`. Это сделано специально:
система не запускает инструкции из Git без вашего согласия.

## Несколько AI работают как команда

Все используют одну `.agents`, но не перезаписывают ответы друг друга. Например,
Claude выполняет задачу, Gemini и Kimi проверяют, а Codex принимает итог:

```bash
./scripts/agents.sh team init release \
  --objective "Подготовить выпуск" --coordinator codex \
  --member claude --member gemini --member kimi

./scripts/agents.sh team task release implementation \
  --title "Сделать изменение" --objective "Подготовить проверенный результат" \
  --role engineer --worker claude --reviewer gemini --reviewer kimi \
  --scope scripts --accept "Все тесты проходят"

./scripts/agents.sh team status release
```

Файлы проекта лежат в `workspace/projects/release/`. Их можно открыть в любом
подключённом AI-приложении или передать через Git. Полный сценарий: [совместная
работа](docs/WORKSPACE.md).

## Что значит `export`

Для обычного использования эта команда не нужна.

`export` создаёт небольшую памятку о конкретной установке. В ней записано:

- какие наборы возможностей были выбраны;
- какие AI-приложения были подключены;
- какая версия `.agents` использовалась.

В ней **нет** промтов, skills, проектов, паролей и других файлов. Наработки
переносит Git. `export` нужен только тогда, когда на другом компьютере важно
повторить ту же версию `.agents` и те же подключения.

```bash
./scripts/agents.sh status
./scripts/agents.sh export ./agents.lock.json
```

Файл `agents.lock.json` и есть эта памятка. После клонирования той же версии
репозитория на новом компьютере:

```bash
./scripts/agents.sh restore ./agents.lock.json
./scripts/agents.sh doctor
```

Технические гарантии и ограничения описаны в [подробном руководстве по восстановлению](docs/PORTABILITY.md).

Хотите понять устройство целиком: [как работает `.agents`](docs/HOW_IT_WORKS.md).

## Если что-то не работает: status

`status` нужен для диагностики. Проверять его каждый день не нужно.

- `current`: установленная копия соответствует источнику;
- `missing`: управляемый объект отсутствует;
- `managed-stale`: источник обновился, установленная копия ещё старая;
- `locally-modified`: установленный объект изменён пользователем;
- `host-conflicting`: подключение хоста отсутствует или занято чужим объектом.

`status` показывает состояние установки. `doctor` проверяет шире: каталог,
профили, структуру репозитория, запрещённые файлы и подключения. Если что-то
не в порядке, команда завершится с ошибкой.

| Если вы хотите… | Выберите при установке |
| --- | --- |
| Разрабатывать и проверять код | «Код» |
| Исследовать рынок, делать маркетинг и запуски | «Исследования и маркетинг» |
| Писать документацию, статьи и продуктовые тексты | «Тексты и документы» |
| Проектировать интерфейсы | «Дизайн интерфейсов» |
| Планировать и делать видео | «Видео» |
| Работать с большими задачами и передачей контекста | «Сложные задачи» |
| Использовать локального AI-помощника | «Локальный AI» |

Общие правила безопасности, проверки качества и базовые помощники добавятся
автоматически. Разбираться в их устройстве не нужно.

## Безопасность и устройство

В lock-файле есть только версия схемы, версия `.agents`, полный commit SHA,
профили, компоненты и AI-приложения. В нём нет путей, команд, URL, переменных
окружения, секретов и содержимого файлов. Ваши локальные изменения и файлы,
которыми `.agents` не управляет, останутся на месте. Конфликт не решается молча:
нужно ваше подтверждение.
