`.agents` — ваша общая рабочая папка для AI. В ней хранятся правила, skills, промты, специалисты и другие наработки. Codex, Claude, Gemini, Kimi и будущие инструменты можно подключать к одной папке по отдельности или одновременно.

Это не новая нейросеть. Это независимый слой между вашими материалами и нейросетями: сменился компьютер, аккаунт или AI-инструмент — ваши наработки остаются у вас.

## Зачем это нужно

| Ситуация | Что даёт `.agents` |
| --- | --- |
| Claude заблокирован или закончился лимит | Подключаете Codex, Gemini или Kimi и продолжаете работу с теми же skills и правилами |
| Купили новый компьютер | Клонируете свою папку `.agents`, запускаете установку и возвращаете рабочую среду |
| Один AI пишет код, другой лучше проверяет | Даёте им разные задачи, а результаты и проверки храните вместе |
| Собрали полезные промты, правила и процессы | Они лежат в вашем Git-репозитории, а не заперты в одном аккаунте |
| Завтра появился новый формат для AI | Добавляете новый тип папки; старые данные не нужно переделывать |

## Быстрый старт: три шага

### 1. Установите

Нужны Git и Python 3. На macOS, Linux или WSL:

```bash
git clone https://github.com/bearatol/.agents.git
cd .agents
./scripts/agents.sh setup
```

На Windows:

```powershell
git clone https://github.com/bearatol/.agents.git
Set-Location .agents
.\scripts\agents.ps1 setup
```

Установка сама спросит:

- чем вы занимаетесь: кодом, текстами, видео, исследованиями или всем сразу;
- какими AI-приложениями вы пользуетесь.

Можно выбрать несколько вариантов. Перед изменениями вы увидите подтверждение.

### 2. Перезапустите выбранный AI-инструмент

После этого AI-инструмент увидит общие skills и настройки, которые он поддерживает.

### 3. Дайте обычную задачу

Например:

> Проверь этот проект на ошибки. Сначала составь короткий план, затем внеси изменения и покажи результаты тестов.

Готово. Для обычной работы больше ничего делать в терминале не нужно.

## Хотите сразу всё и несколько AI

Одной командой можно установить все возможности и подключить несколько AI:

```bash
./scripts/agents.sh setup --work all \
  --app codex --app claude --app gemini --app kimi
```

На Windows:

```powershell
.\scripts\agents.ps1 setup -Work all -App codex,claude,gemini,kimi
```

Позже можно подключить ещё один AI, не переустанавливая остальное:

```bash
./scripts/agents.sh connect kimi
```

## Что сохраняется

В Git-репозитории `.agents` могут храниться:

- ваши правила и промты;
- skills и специалисты;
- настройки моделей и описания подключений;
- общие задачи, ответы и проверки нескольких AI;
- любые будущие типы данных в новых папках.

Пароли, API-ключи, авторизация, установленные программы и веса моделей не сохраняются. Это специально: секреты не должны попадать в Git.

## Как сохранить свою наработку

Пример для собственного skill:

```bash
./scripts/agents.sh library add skill my-skill ./my-skill
./scripts/agents.sh library trust skill my-skill
./scripts/agents.sh library activate skill my-skill
./scripts/agents.sh connect codex claude gemini kimi
```

Сначала материал сохраняется, затем вы явно подтверждаете, что проверили его. После активации подключённые AI смогут использовать skill. Другие типы — `rule`, `prompt`, `agent`, `mcp`, `model` или любое новое имя — уже можно хранить; их подключение будет добавляться через соответствующие адаптеры.

## Переезд на новый компьютер

Если вы не добавляли личные материалы, просто снова клонируйте `.agents` и запустите `setup`.

Если вы храните собственные наработки, используйте свой приватный Git-репозиторий. На новом компьютере:

```bash
git clone YOUR_PRIVATE_REPOSITORY .agents
cd .agents
./scripts/agents.sh setup
./scripts/agents.sh library check
./scripts/agents.sh doctor
```

Git переносит ваши файлы. `setup` возвращает общую среду и подключения. Личные
skills в текущей версии нужно снова явно активировать командой
`library activate skill НАЗВАНИЕ`: система не включает инструкции из Git без
вашего подтверждения.

## Несколько AI работают как команда

Общие настройки лежат в `.agents`, а задания и ответы разных AI не перезаписывают друг друга. Например, Claude выполняет задачу, Gemini и Kimi проверяют, Codex принимает итог:

```bash
./scripts/agents.sh team init release \
  --objective "Подготовить выпуск" --coordinator codex \
  --member claude --member gemini --member kimi

./scripts/agents.sh team task release implementation \
  --title "Сделать изменение" --objective "Подготовить проверенный результат" \
  --role engineer --worker claude --reviewer gemini --reviewer kimi \
  --scope scripts --accept "Все тесты проходят"

./scripts/agents.sh team status release
```

Файлы проекта находятся в `workspace/projects/release/`. Их можно читать из любого AI-приложения или синхронизировать через Git. Полный сценарий результата, проверок и принятия: [совместная работа](docs/WORKSPACE.md).

## Что значит `export`

Для обычного использования эта команда не нужна.

`export` создаёт маленькую памятку для точного восстановления установки. В ней записано:

- какие наборы возможностей были выбраны;
- какие AI-приложения были подключены;
- какая версия `.agents` использовалась.

В памятке **нет** ваших промтов, skills, проектов, паролей или файлов. Ваши наработки переносит Git. `export` нужен только когда важно воспроизвести на другом компьютере именно ту же версию и тот же набор подключений.

```bash
./scripts/agents.sh status
./scripts/agents.sh export ./agents.lock.json
```

Получившийся `agents.lock.json` — и есть эта памятка. После клонирования той же версии репозитория на новом компьютере:

```bash
./scripts/agents.sh restore ./agents.lock.json
./scripts/agents.sh doctor
```

Технические гарантии и ограничения описаны в [подробном руководстве по восстановлению](docs/PORTABILITY.md).

Хотите понять устройство целиком: [как работает `.agents`](docs/HOW_IT_WORKS.md).

## Что означает status

Этот раздел нужен только при диагностике. В нормальной работе смотреть `status`
каждый день не требуется.

- `current` — установленная копия соответствует источнику;
- `missing` — управляемый объект отсутствует;
- `managed-stale` — источник обновился, установленная копия ещё старая;
- `locally-modified` — установленный объект изменён пользователем;
- `host-conflicting` — подключение хоста отсутствует или занято чужим объектом.

`status` показывает состояние установленной среды. `doctor` дополнительно проверяет каталог, профили, структуру репозитория, запрещённые артефакты и интеграцию хостов. Небезопасное или неполное состояние возвращает ненулевой код.

## Безопасность и устройство

Lock-файл содержит только версию схемы, версию экосистемы, полный commit SHA, профили, компоненты и хосты. В нём нет путей, команд, URL, переменных окружения, credentials или содержимого файлов. Локальные изменения и неуправляемые файлы сохраняются; конфликт требует явного решения.
